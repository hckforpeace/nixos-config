# NixOS configuration

Flake-based NixOS config, pinned to the `nixos-26.05` branch of nixpkgs.
Everything the system is built from lives in this repo; there is no
hand-edited `/etc/nixos/configuration.nix` in the picture.

The repo is checked out at `/home/pierre/nixos-config`. It does not need to be
in `/etc/nixos` -- a flake is referenced by path, so the commands below work
from wherever the clone lives.

## Layout

```
flake.nix              inputs (nixpkgs) + one output per machine
flake.lock             the exact nixpkgs commit; this is what makes rebuilds reproducible

hosts/<name>/          MACHINE-SPECIFIC -- wrong on any other machine
  nixos-pb/              the ASUS TUF A15 laptop; the real machine
    default.nix            hostname, stateVersion, the import list
    hardware-configuration.nix   generated by nixos-generate-config
    disks.nix              systemd-boot + the LUKS container UUID
    quirks.nix             hardware workarounds for this model
  vm-test/               throwaway VirtualBox VM; see "Testing in a VM"

modules/               PORTABLE -- should work unchanged on a new host
  base.nix               flakes, allowUnfree, locale, timezone, zsh, nix-ld, core CLI tools
  networking.nix         NetworkManager + nm-applet, tailscale, bluetooth + blueman
  desktop.nix            X11, i3, lightdm, clipmenu, firefox, fonts, desktop utilities
  users.nix              the pierre account: groups, login shell, per-user packages
  optional/              not imported by default; opt in per host
    ollama.nix             local LLM inference (CPU build; see the note in the file)
    apps.nix               dbeaver, discord, texlive, easyeda
    virtualisation.nix     VirtualBox host, needed to run hosts/vm-test

packages/              locally packaged software
  easyeda/               EasyEDA standalone client, FHS-wrapped
```

The split exists so that bringing up a second machine means writing a new
`hosts/` directory and touching nothing under `modules/`.

Not managed here: dotfiles. `~/.config` is still a set of loose files, so a
fresh install reproduces the system but not the i3 / picom / zsh setup.

## Rebuilding

```sh
cd ~/nixos-config
sudo nixos-rebuild switch --flake .#nixos-pb
```

Build without activating, to check a change compiles:

```sh
nixos-rebuild build --flake .#nixos-pb
```

Build and keep the current system as the boot default until the next reboot:

```sh
sudo nixos-rebuild test --flake .#nixos-pb
```

Two things that bite:

- **Always pass `--flake`.** Plain `nixos-rebuild switch` ignores this repo and
  falls back to `/etc/nixos`, which is not where the config lives.
- **Flakes only see files tracked by git.** A new file that has not been
  `git add`-ed is invisible to the build, and the failure reads as a confusing
  "file not found" or "attribute missing". `git add` first.

Rolling back does not need the repo at all -- previous generations are in the
boot menu, or:

```sh
sudo nixos-rebuild switch --rollback
```

## Updating nixpkgs

```sh
nix flake update          # move forward along nixos-26.05
```

To move to a different NixOS release, edit the branch in `flake.nix` and
re-run `nix flake update`. Bumping a release normally also means reading the
release notes; do not change `system.stateVersion` on an existing machine.

`hosts/nixos-pb/disks.nix` caps the boot menu at 20 generations, so the ESP
cannot fill up and block a rebuild.

## Installing on a new machine

The flake drives the install itself. The one step that is not flake-based is
`nixos-generate-config`, which only probes the hardware and writes a file.

1. Boot the NixOS installer ISO.
2. Partition and mount at `/mnt`. For the same layout as `nixos-pb`: an ESP on
   `/mnt/boot`, and a LUKS container named `cryptlvm` holding an LVM volume
   group `vg0` with root / home / swap.
3. Probe the hardware:
   ```sh
   nixos-generate-config --root /mnt
   ```
4. Clone this repo and create the host directory:
   ```sh
   mkdir -p hosts/<name>
   cp /mnt/etc/nixos/hardware-configuration.nix hosts/<name>/
   cp hosts/nixos-pb/{default.nix,disks.nix,quirks.nix} hosts/<name>/
   ```
5. Fix the copied files:
   - `networking.hostName` in `default.nix`
   - the LUKS UUID in `disks.nix` (`lsblk -f` to find it)
   - `system.stateVersion` -- set it to the release you are installing
   - review `quirks.nix`; it is ASUS TUF A15 specific and probably wrong
6. Add an output to `flake.nix`:
   ```nix
   nixosConfigurations.<name> = nixpkgs.lib.nixosSystem {
     system = "x86_64-linux";
     modules = [ ./hosts/<name> ];
   };
   ```
7. Install, with flakes enabled explicitly since the ISO does not enable them:
   ```sh
   git add -A
   nixos-install --flake .#<name> \
     --option experimental-features 'nix-command flakes'
   ```
8. Reboot, then set a real password: `passwd pierre`.

## Testing in a VM

`hosts/vm-test` imports every module under `modules/` and nothing
machine-specific. Building and booting it is how you check that a change to a
portable module works somewhere other than this laptop -- and that the "bring
up a second machine by writing a new `hosts/` directory" story actually holds.

The host machine needs the VirtualBox hypervisor, which is not what installing
the `virtualbox` package gives you. Import `modules/optional/virtualisation.nix`
into the host's `hosts/<name>/default.nix` (it is there, commented out, in
`hosts/nixos-pb/default.nix`), rebuild, and **reboot**: the hypervisor is a
kernel module and it is loaded at boot.

Build the appliance and boot it:

```sh
nix build .#nixosConfigurations.vm-test.config.system.build.virtualBoxOVA
VBoxManage import result/*.ova
VBoxManage startvm nixos-vm-test
```

Log in as `pierre`, password `test` (set in `hosts/vm-test/default.nix`).
A pass looks like: lightdm prompts, the i3 session starts, `nmcli` shows a
connection, and the tools from `modules/desktop.nix` are on `$PATH`. Backlight
and bluetooth have no hardware behind them in a VM, so those two failing tells
you nothing. i3 asking to generate a config is also expected -- dotfiles are
not managed here.

Re-import after a change, then throw the VM away; it is not a machine to keep:

```sh
VBoxManage unregistervm nixos-vm-test --delete
```

For the narrower question "does it build and boot at all", skip VirtualBox and
use QEMU, which needs no host configuration and no reboot:

```sh
nixos-rebuild build-vm --flake .#vm-test
./result/bin/run-vm-test-vm
```

## Notes

- `programs.zsh.enableCompletion = false` is deliberate; completion is set up
  in the user's own zsh config.
- `programs.nix-ld.enable` is what lets unpatched upstream binaries -- tarballs,
  language-specific installers -- find a runtime linker.
- pipewire is not declared anywhere. `services.xserver.enable` turns it on via
  nixpkgs' `graphical-desktop.nix`, so it reproduces on a fresh install.
- `modules/desktop.nix` installs `brightnessctl` and adds its udev rules; the
  i3 brightness keybinds need both, plus the `video` group from `users.nix`.
- The RTX 3070 Ti in this laptop is not configured. `nouveau` binds it and the
  Radeon 680M drives the display. Enabling the proprietary driver needs a
  `hardware.nvidia` block with this machine's PRIME bus IDs
  (`amdgpuBusId = "PCI:6:0:0"`, `nvidiaBusId = "PCI:1:0:0"`). `optional/ollama.nix`
  uses the CPU build of ollama for the same reason.
